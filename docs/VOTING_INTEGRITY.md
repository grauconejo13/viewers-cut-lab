# Voting Integrity

## Purpose

Vote integrity protects the audience signal used for creative development. It is
not an anti-fraud guarantee and must not imply fictional demo activity is real.

## Prototype ballot model

Phase 4A uses a client-generated anonymous session identifier and a server-side
in-memory repository to reject a second completed cut for the same movie and
session. The route validates all movie, question, and option IDs against the
curated definitions, then calculates counts and one-decimal percentages from
trusted stored submissions only. This store is development-only and resets on
server restart; Phase 9 replaces it with durable cloud storage.

- One ballot contains all selected answers for one movie round.
- The anonymous prototype permits one ballot per session per round; the session
  identifier is securely generated by the server.
- The server, not localStorage, enforces duplicate prevention.
- LocalStorage may improve user experience but is never the authority for
  eligibility or validity.
- Trusted and raw ballot counts remain distinguishable; public results use
  trusted ballots and label demo data.

## Deterministic status model

| Status | Meaning | Action |
| --- | --- | --- |
| Trusted | Passed defined integrity rules | Include in percentages and AI input |
| Held | Needs review or a later rule decision | Exclude from trusted percentages |
| Rejected | Violates a deterministic rule | Exclude from valid totals |

The Vote Integrity Service performs deterministic duplicate, rate, and
suspicious-pattern checks. Gemini may summarize aggregate patterns, but never
decides whether a ballot is valid.

## Required checks

- Reject a duplicate ballot for the same server session and round.
- Add rate limits before public deployment.
- Hold or reject defined suspicious patterns with a recorded reason.
- Validate each ballot and choice ID on the server against the current round.
- Calculate option percentages from trusted ballots eligible for that question.

## Later hardening

The real product is planned to use Firebase Authentication or Google sign-in,
stronger abuse controls, audit logs, and reviewed policy rules. Advanced device
fingerprinting is outside the first MVP.
